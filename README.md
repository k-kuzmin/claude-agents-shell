# Claude Agents Shell

Десктопная оболочка над терминалом для параллельной работы с несколькими сессиями
[Claude Code](https://claude.com/claude-code).

Одно окно: слева список проектов, справа вкладки, каждая вкладка — отдельная интерактивная
сессия `claude` в своём PowerShell. Внутри вкладки работает настоящий терминал с настоящим TUI.
Оболочка **не** разбирает вывод агента, **не** рисует свой чат и **не** подменяет собой CLI.

![Главное окно](docs/mockup.svg)

## Зачем

Запуск новой сессии по проекту — один клик, без диалогов. Возврат к прошлой — один клик и выбор
из списка. Пять одновременных сессий по трём проектам живут в одном окне, и набор текста в активной
вкладке не тормозит от того, что в трёх соседних идёт `dotnet build`.

## Как это устроено

```
WPF-процесс
├── ОДИН экземпляр WebView2 на всё окно
│   └── страница с N экземплярами xterm.js (по одному на вкладку)
└── N пар процессов: pwsh → claude (каждая в своём ConPTY)
```

Три решения определяют всё остальное:

**Один WebView2 на окно, а не на вкладку.** Контрол на вкладку означает процесс рендерера
на каждую вкладку — это главный источник просадок и памяти. Переключение вкладки — смена
видимости контейнера на странице, ровно одно сообщение моста и ни одной перерисовки буфера.

**Вывод PTY передаётся как base64 сырых байтов.** Декодировать чанки в строку на стороне C#
нельзя: чанк рвётся посреди UTF-8 последовательности и ломает кириллицу и рамки TUI. Состояние
декодера держит xterm.js.

**Байты склеиваются в пачки** — кадр 16 мс или 64 КБ. ConPTY отдаёт чтения по ~130 байт;
без склейки на страницу уходило бы восемь тысяч сообщений на мегабайт вывода вместо сорока.

## Состояние

| Этап | Состояние |
|---|---|
| M1 — мост ConPTY ↔ WebView2 | готов, принят |
| M2 — проекты и вкладки | готов, принят |

## Требования

- Windows 10 1809+ или Windows 11, x64 (ConPTY требует 1809+)
- .NET 8 SDK
- [WebView2 Runtime](https://developer.microsoft.com/microsoft-edge/webview2/) (Evergreen)
- Node.js — только чтобы разложить ассеты xterm.js локально
- `pwsh` или `powershell.exe`; `claude` в `PATH`

## Сборка и запуск

```powershell
cd web
npm install
npm run vendor      # раскладывает xterm.js и аддоны в web/vendor
cd ..

dotnet build ClaudeAgentsShell.sln
.\src\ClaudeAgentsShell.App\bin\Debug\net8.0-windows10.0.17763.0\ClaudeAgentsShell.exe
```

`web/vendor/` не хранится в репозитории, поэтому `npm run vendor` нужен на чистом клоне.
Ассеты отдаются WebView2 через `SetVirtualHostNameToFolderMapping` — **никаких CDN**,
приложение работает без интернета.

```powershell
dotnet test ClaudeAgentsShell.sln
dotnet format --verify-no-changes
```

## Структура

```
src/ClaudeAgentsShell.Domain        модели, без зависимостей вообще
src/ClaudeAgentsShell.Application   порты (интерфейсы), сценарии
src/ClaudeAgentsShell.Terminal      ConPTY, мост, протокол сообщений
src/ClaudeAgentsShell.Sessions      projects.json, история, хуки
src/ClaudeAgentsShell.App           WPF, ViewModel, DI-композиция
web/                                страница терминалов, xterm.js локально
tests/                              модульные тесты
```

Зависимости направлены внутрь: `App → Sessions/Terminal → Application → Domain`.
Обратных ссылок нет. Прикладной код работает через порты: `IPtySession`, `ITerminalBridge`,
`IProjectStore`, `ISessionHistoryReader`, `IHookListener` и остальные.
`Domain` не зависит ни от чего.

## Данные

`%APPDATA%\ClaudeAgentsShell\` — список проектов, файл настроек с хуками, раскладка.
Запись `projects.json` атомарная.

Файлы сессий Claude Code в `~/.claude/projects` приложение **только читает**: ни удаления,
ни записи. В проект пользователя не пишется ничего — настройки для хуков генерируются
в каталоге приложения и передаются сессии через `--settings`.

Состояние вкладки берётся из хуков Claude Code (`SessionStart`, `Stop`, `SessionEnd`), а не
из разбора вывода. Не сработали хуки — вкладка живёт без маркера состояния, и это нормально.
