# ТЗ: Claude Agents Shell

Десктопная оболочка над терминалом для параллельной работы с несколькими сессиями Claude Code.
Документ предназначен как вход для кодящего агента: он описывает целевое поведение, архитектуру и критерии приёмки, но не диктует построчную реализацию.

---

## 1. Цель

Одно окно, в котором:

- слева список проектов (рабочих каталогов);
- справа вкладки, каждая вкладка — отдельная интерактивная сессия `claude` в своём PowerShell;
- запуск новой сессии по проекту — один клик, без диалогов;
- возврат к прошлой сессии — один клик и выбор из списка.

Внутри вкладки работает настоящий терминал с настоящим TUI Claude Code. Оболочка **не** разбирает вывод агента, **не** рисует свой чат и **не** подменяет собой CLI.

### Не входит в рамки

- Собственный чат-интерфейс поверх Agent SDK.
- Парсинг вывода агента, показ диффов, встроенный редактор или git-клиент.
- Управление настройками Claude Code (модель, права, MCP) из GUI — всё это делается внутри самой сессии.
- Мобильная/веб-версия, кросс-платформенность.

---

## 2. Платформа и стек

| Что | Чем |
|---|---|
| ОС | Windows 10 1809+ / Windows 11, x64 (ConPTY требует 1809+) |
| Рантайм | .NET 8 или новее |
| UI-оболочка | WPF |
| Рендер терминала | WebView2 (Evergreen) + xterm.js 5.x |
| Псевдотерминал | ConPTY через `Pty.Net` (допустима прямая обвязка над `CreatePseudoConsole`, если библиотека не подойдёт) |
| Оболочка в PTY | `pwsh` (fallback на `powershell.exe`, если pwsh не найден) |

Аддоны xterm.js: `addon-fit` обязателен, `addon-webgl` с откатом на canvas-рендерер, `addon-unicode11` — включить, иначе ломается ширина символов в выводе агента.

**Все ассеты xterm.js кладутся локально** и отдаются в WebView2 через `SetVirtualHostNameToFolderMapping`. Загрузка с CDN запрещена: приложение должно работать без интернета.

## 3. Архитектура

### 3.1 Процессы

```
WPF-процесс
├── ОДИН экземпляр WebView2 на всё окно
│   └── страница с N экземплярами xterm.js (по одному на вкладку)
└── N пар процессов: pwsh → claude (каждая в своём ConPTY)
```

**Критично:** ровно один WebView2 на окно. Отдельный контрол WebView2 на вкладку означает отдельный процесс рендерера на каждую вкладку — это основной источник просадок и памяти. Переключение вкладки — это смена `display` у контейнеров терминалов плюс `fit()` на том, который стал видимым.

### 3.2 Мост C# ↔ страница

Двусторонний обмен через `PostWebMessageAsString` / `WebMessageReceived`, сообщения — JSON.

Из C# на страницу:

```json
{ "type": "out",    "id": "t1", "b64": "<сырые байты из PTY в base64>" }
{ "type": "create", "id": "t1", "title": "Домовой · sensor repo" }
{ "type": "show",   "id": "t1" }
{ "type": "close",  "id": "t1" }
{ "type": "exited", "id": "t1", "code": 0 }
```

Со страницы в C#:

```json
{ "type": "in",     "id": "t1", "b64": "<байты пользовательского ввода>" }
{ "type": "resize", "id": "t1", "cols": 120, "rows": 34 }
{ "type": "ready",  "id": "t1" }
```

**Вывод передаётся как base64 сырых байтов, а не как строка.** Чанк из PTY может оборваться посередине UTF-8 последовательности; при декодировании в C# по чанкам это даёт «кракозябры» в русском выводе и в рамках TUI. На стороне JS base64 разворачивается в `Uint8Array` и отдаётся в `term.write(bytes)` — xterm.js сам держит состояние декодера.

### 3.3 Поток вывода

1. Читающий цикл PTY складывает байты в буфер вкладки.
2. Буфер сбрасывается на страницу **не чаще одного раза в кадр** (таймер ~16 мс) либо по достижении 64 КБ.
3. `term.write(bytes, callback)` — счётчик незавершённых записей. Если он превышает порог (например 4), чтение из PTY приостанавливается до вызова callback.

Посимвольная или почанковая отправка без склейки — главная причина фризов при `dotnet build` и подобном потоке; склейка обязательна.

### 3.4 Ввод и размер

- `term.onData` → `in` → запись в stdin PTY.
- Изменение размера окна или показ вкладки → `FitAddon.fit()` → `resize` → `pty.Resize(cols, rows)`.
- Ресайз дебаунсится (~80 мс), иначе TUI перерисовывается на каждый пиксель перетаскивания.
- У скрытых вкладок `fit()` не вызывается (нулевые размеры дадут мусорный `resize`), но данные они продолжают получать и парсить.

### 3.5 Память

- Scrollback: 5000 строк на вкладку, настраивается.
- Закрытие вкладки: `term.dispose()`, освобождение PTY, снятие таймеров.
- Утечка проверяется сценарием «открыть и закрыть 20 вкладок подряд» — после GC потребление возвращается к исходному.

## 4. Данные приложения

Каталог данных: `%APPDATA%\ClaudeAgentsShell\`.

### 4.1 `projects.json`

```json
{
  "version": 1,
  "projects": [
    {
      "id": "9f2c…",
      "name": "Домовой",
      "path": "D:\\src\\domovoy",
      "shell": "pwsh",
      "preLaunch": "git fetch --prune",
      "extraArgs": [],
      "order": 0
    }
  ]
}
```

- `preLaunch` — необязательная команда, выполняемая в PTY до запуска `claude`.
- `extraArgs` — дополнительные аргументы командной строки `claude` для этого проекта.
- Запись атомарная: временный файл + `File.Replace`.

### 4.2 `layout.json`

Открытые вкладки на момент выхода: id проекта, id сессии Claude, заголовок, порядок, активная вкладка. При старте приложение **не** восстанавливает сессии автоматически — оно показывает их в списке «недавние», чтобы пользователь сам решил, что поднимать.

## 5. Интеграция с Claude Code

> Всё, что касается внутреннего формата файлов сессий, считается нестабильным. Любой сбой чтения деградирует до «показать файл по имени и дате», но никогда не роняет приложение.

### 5.1 Запуск сессии

1. Стартует `pwsh -NoLogo` в ConPTY с рабочим каталогом проекта.
2. В окружение добавляется `TERM=xterm-256color`.
3. Если задан `preLaunch` — команда пишется в stdin и выполняется.
4. Затем пишется команда запуска:
   - новая сессия: `claude` + `extraArgs`;
   - продолжение конкретной: `claude --resume <session-id>`;
   - продолжение последней: `claude --continue`.

После выхода `claude` пользователь остаётся в живом `pwsh` — вкладка не закрывается сама. Вкладка закрывается только когда завершился сам `pwsh`.

### 5.2 История сессий

Транскрипты лежат в `~/.claude/projects/<slug>/<session-id>.jsonl`, где `<slug>` — путь рабочего каталога с заменой не-буквенно-цифровых символов на дефис. Приложение:

- перечисляет `*.jsonl` в каталоге проекта;
- для каждого файла берёт время изменения, размер и первое сообщение пользователя (для заголовка);
- кэширует разбор по ключу `(путь, mtime, размер)`, чтобы не перечитывать файлы при каждом открытии окна;
- читает файл потоково и останавливается, как только нашёл заголовок — файлы бывают большими;
- обновляет список по `FileSystemWatcher` на каталоге, без периодического опроса.

Файлы сессий приложение **только читает**. Удаление и правка запрещены.

### 5.3 Состояние вкладки

Три состояния: `работает` (агент занят), `ждёт ввода`, `простаивает`.

Источник — хуки Claude Code, а не разбор экрана. Приложение генерирует файл настроек в своём каталоге данных и передаёт его сессии через `--settings`; в проект пользователя ничего не пишется. В хуках регистрируются `SessionStart`, `Stop`, `SessionEnd`; каждый хук отправляет JSON со stdin на локальный endpoint приложения (`http://127.0.0.1:<порт>/hook`, порт выбирается свободный при старте, слушать только loopback).

- `SessionStart` даёт `session_id` — так вкладка узнаёт, какой сессии она соответствует, и заголовок вкладки обновляется.
- `Stop` переводит вкладку в «ждёт ввода».
- Первый ввод пользователя после `Stop` переводит обратно в «работает».
- `SessionEnd` снимает маркер.

Если хуки не сработали (сессия запущена мимо приложения, настройки не подхватились), вкладка живёт без маркера состояния. Это допустимая деградация; ошибку показывать не нужно.

**Строку статуса Claude Code приложение не трогает и не дублирует** — контекст и лимиты пользователь уже видит внутри терминала.

## 6. Интерфейс

Ориентир — макет `claude-agents-shell-mockup.html`. Размеры и цвета оттуда, поведение описано ниже.

### 6.1 Окно

Заголовок приложения, под ним две колонки: панель проектов 256 px и область вкладок. Нижней строки статуса нет.

### 6.2 Панель проектов

- Заголовок «ПРОЕКТЫ» и кнопка добавления проекта (иконка папки с плюсом).
- Строка проекта: имя, под ним путь и текущая ветка git моноширинным шрифтом.
- В покое справа — маркер состояния и число открытых сессий проекта, либо тире.
- При наведении вместо них появляются две кнопки:
  - **+** — новая сессия в этом проекте, сразу открывается вкладка;
  - **часы со стрелкой** — окно истории сессий этого проекта.
- Клик по строке переключает на активную вкладку проекта; если открытых нет — ничего не делает.
- Контекстное меню: открыть папку в проводнике, настройки проекта, убрать из списка.
- Ветка определяется чтением `.git/HEAD`, обновляется по `FileSystemWatcher`. Не git-репозиторий — поле просто пустое.

### 6.3 Вкладки

- Точка состояния, заголовок `<проект> · <короткое имя сессии>`, крестик.
- Короткое имя — первые слова первого сообщения пользователя; до этого момента «новая сессия».
- Справа в полосе вкладок — счётчик «N ждёт ввода», кликабельный: переключает на первую такую вкладку.
- Горячие клавиши: `Ctrl+T` — новая сессия в активном проекте, `Ctrl+W` — закрыть вкладку (с подтверждением, если процесс жив), `Ctrl+Tab` — следующая, `Ctrl+1..9` — по номеру.
- Перетаскивание вкладок меняет порядок.

### 6.4 Окно истории

Модальное окно над главным: поиск по первому сообщению, фильтр по проектам, список строк «первое сообщение / дата, число сообщений, ветка, короткий id». Навигация стрелками, `Enter` открывает вкладку с `--resume`, `Esc` закрывает.

### 6.5 Настройки проекта

Диалог добавления и редактирования: путь (с выбором папки), отображаемое имя, оболочка, команда перед запуском, дополнительные аргументы. Показывает, найдены ли в каталоге `CLAUDE.md` и `.mcp.json` — справочно, приложение их не читает и не меняет.

## 7. Требования к производительности

Проверяется на пяти одновременных сессиях:

1. В трёх вкладках одновременно идёт шумный вывод (`dotnet build` на среднем решении). Набор текста в активной вкладке отзывается без заметной задержки, символ появляется в пределах ~100 мс.
2. Переключение вкладки происходит мгновенно и не перерисовывает содержимое заново — буфер xterm.js сохраняется.
3. Вывод в фоновых вкладках не вызывает перерисовку: при переключении на них видна вся история.
4. Потребление памяти самим приложением (без дочерних `pwsh` и `claude`) стабилизируется и не растёт монотонно за час работы.
5. Ресайз окна не приводит к «лесенке» и мусору в TUI.

## 8. Краевые случаи

- **Каталог проекта исчез** — строка помечается как недоступная, запуск сессии заблокирован, приложение не падает.
- **`claude` не найден в PATH** — сессия всё равно открывается, пользователь видит ошибку pwsh как есть.
- **`pwsh` не установлен** — откат на `powershell.exe`, состояние отражено в настройках проекта.
- **WebView2 Runtime не установлен** — понятное сообщение при старте со ссылкой на установщик, не стек-трейс.
- **Процесс сессии упал** — вкладка остаётся открытой с пометкой о коде выхода, кнопка «перезапустить».
- **Каталога `~/.claude/projects/<slug>` нет** — история пустая, это не ошибка.
- **Битая строка в `.jsonl`** — строка пропускается, разбор продолжается.
- **Вставка большого текста** — bracketed paste не ломается склейкой чанков.

## 9. Этапы

### M1 — мост PTY, одна вкладка

WPF-окно, один WebView2, один xterm.js, один `pwsh` в ConPTY. Запуск `claude` вручную внутри.

**Приёмка:** TUI Claude Code рисуется корректно; ресайз окна не ломает рамки; русский текст и эмодзи не рассыпаются; вставка многострочного текста работает; вывод `dotnet build` не подвешивает UI.

Это самый рискованный этап — дальше двигаться, только когда он закрыт.

### M2 — проекты и вкладки

`projects.json`, панель проектов, мультиплексор вкладок, кнопка «+» на строке проекта, запуск `claude` командой в stdin, горячие клавиши.

**Приёмка:** пять сессий по трём проектам, переключение мгновенное, критерии раздела 7 выполнены.

### M3 — история и resume

Чтение `~/.claude/projects`, кэш разбора, окно истории, `--resume` и `--continue`.

**Приёмка:** сессия, созданная вчера, поднимается из списка и продолжается с прежним контекстом; список открывается без заметной паузы при сотне файлов сессий.

### M4 — состояние сессий

Генерация файла настроек, `--settings`, локальный приёмник хуков, точки состояния на вкладках, счётчик ожидающих, заголовки вкладок из первого сообщения.

**Приёмка:** агент закончил ответ в фоновой вкладке — её точка меняет цвет в пределах секунды; работа без хуков деградирует мягко.

### M5 — доводка

Настройки проекта, восстановление раскладки, контекстные меню, перетаскивание вкладок, обработка краевых случаев из раздела 8.

## 10. Структура решения

```
ClaudeAgentsShell.sln
├── src/ClaudeAgentsShell.App        — WPF, окна, ViewModel
├── src/ClaudeAgentsShell.Terminal   — ConPTY, мост, протокол сообщений
├── src/ClaudeAgentsShell.Sessions   — projects.json, чтение истории, приёмник хуков
├── web/                             — страница терминалов, xterm.js и аддоны
└── tests/                           — модульные тесты на разбор .jsonl, slug пути, склейку чанков
```

Тестами обязательно покрыть: вычисление slug каталога проекта, разбор `.jsonl` (включая битые строки и пустые файлы), склейку и разбиение UTF-8 на границах чанков.
