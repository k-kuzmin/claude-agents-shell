# Стартовый промпт

Разложить в пустом репозитории перед запуском:

```
CLAUDE.md
.claude/agents/reviewer.md
.claude/agents/perf-auditor.md
docs/TZ.md          (файл TZ-claude-agents-shell.md)
docs/mockup.html    (файл claude-agents-shell-mockup.html)
```

Дальше — один промпт в корне репозитория:

---

Прочитай `CLAUDE.md`, `docs/TZ.md` и `docs/mockup.html` целиком, один раз. Реализуй приложение Claude Agents Shell по этому ТЗ.

Работай как оркестратор по правилам `CLAUDE.md`: контракты пишешь сам, реализацию делегируешь сабагентам, независимые блоки запускаешь параллельно одним сообщением, после каждого блока гоняешь `reviewer`, в конце этапа — `reviewer` и `perf-auditor`. Веди `docs/PROGRESS.md`.

Порядок:

1. Создай решение, проекты по структуре из раздела 3 `CLAUDE.md`, настрой DI, nullable, предупреждения как ошибки, тестовый проект.
2. Зафиксируй контракты: порты, доменные модели, протокол сообщений моста из раздела 3.2 ТЗ. Это единственный код, который ты пишешь сам.
3. Этап M1 — мост ConPTY ↔ WebView2, одна вкладка, последовательно, одним агентом. Закончив, собери, прогони тесты, запусти `reviewer` и `perf-auditor` и **остановись**: мне нужно самому проверить, как рисуется TUI, ресайз, кириллица и вставка. Дальше не иди без моего подтверждения.
4. После моего «ок» — этапы M2–M5 по ТЗ, каждый через план, параллельные блоки, ревью и аудит.

Если в ТЗ чего-то не хватает или есть противоречие — спроси, не додумывай.

---

## Почему M1 — остановка

Всё остальное можно проверить сборкой и тестами. Корректность TUI под чужим ConPTY проверяется только глазами: рамки, ширина эмодзи, поведение при ресайзе, bracketed paste. Агент не может это увидеть, а если мост неправильный, на нём будет построено всё приложение.

Если хочется совсем без остановок — убери пункт 3 про подтверждение. Но тогда закладывайся на то, что первый прогон придётся откатывать целиком.
